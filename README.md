앱 이름은 아직 정하지 않았다.

## 환경 준비

```bash
npm install
npm run dev   # http://localhost:3000
```

**이게 전부다.** 서버도 `.env.local`도 계정 가입도 필요 없다 — 데이터는 브라우저 `localStorage`에만 저장된다. 첫 화면 아래 띠에 "시뮬레이션 모드 · 사용자 20명 …"이 뜨면 준비 끝이다.

## 알아둘 것

- **서버가 없다.** Supabase도, 어떤 백엔드도 쓰지 않는다. 데이터는 브라우저의 `localStorage`/`sessionStorage`뿐이다
- **업무 규칙은 전부 `lib/mock/api.ts`에 있다.** 하루 신청 상한 5건, 차단 반영, 신고 임계치는 여기 함수 안에만 구현돼 있다. 화면 코드는 이 함수를 부르고 오류 메시지를 그대로 보여주기만 한다. 화면에서 상한을 세거나 차단 여부를 판단하는 코드를 쓰면 규칙이 두 벌이 되어 어긋난다
- **`lib/mock/**` 와 `lib/types.ts` 는 A만 고친다.** 데이터 모양·업무 규칙 변경이 필요하면 A에게 요청한다
- **접근 차단(로그인 안 됨 등)은 각 페이지의 `useEffect`가 한다.** 새 보호 페이지를 만들 때는 `app/admin/page.tsx`를 참고한다
- **두 계정을 동시에 테스트하려면 같은 브라우저에서 탭을 여러 개 연다.** 로그인 정보는 탭마다 따로(`sessionStorage`)지만 실제 데이터는 탭끼리 공유(`localStorage`)돼서, 신청·채팅이 탭 사이에 실제로 오간다. 서로 다른 브라우저·기기끼리는 데이터가 전혀 공유되지 않는다
- **남이 만드는 컴포넌트를 새로 만들지 않는다.** 늦어지면 임시로 막아두고, 나오면 반드시 교체한다. 누가 무엇을 만드는지는 자기 트랙 체크리스트의 "주고받는 것" 표에 있다
- 색은 `app/globals.css`의 `--brand-*` 토큰을 쓴다 (`bg-brand-600` 처럼)
- 화면 문구는 전부 한국어

## 현재 상태

Phase 0·1·7(기반·로그인·관리자)이 끝났다. 자세한 진행 상황은 각 트랙의 체크리스트를 본다.

**로그인은 시뮬레이션 전용이다.** `@kyonggi.ac.kr` 이메일 주소만 입력하면 서버 없이 바로 로그인된다. 이메일 주소를 아는 사람은 그 계정으로 들어올 수 있으므로, 실제 학생을 받는 서비스가 된다면 진짜 인증으로 되돌려야 한다. 자세한 내용은 [CLAUDE.md](CLAUDE.md)와 SPEC.md 7장에 있다.

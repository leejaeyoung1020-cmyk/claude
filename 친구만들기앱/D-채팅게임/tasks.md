## 시작 전에 알아야 할 것

**시작 조건:** A가 Phase 0을 끝내면 시작한다. **시드 데이터에 수락된 대화방 1개와 메시지 6개가 들어 있으므로**, C의 친구 신청 기능이 완성되기를 기다리지 않고 바로 채팅 화면을 만들 수 있다.

**실시간 기능이 이 프로젝트에서 기술적으로 가장 까다로운 부분이다.** 팀에 실력 차가 있다면 D는 경험 있는 사람이 맡는 게 좋다.

**막히면 가장 먼저 의심할 것**

메시지가 상대 화면에 안 뜨면, 코드를 고치기 전에 **Phase 0에서 아래가 실행됐는지** A에게 확인한다. 이게 빠져 있으면 코드가 아무리 맞아도 동작하지 않는다.

```sql
alter publication supabase_realtime add table messages;
```

**내가 남에게서 받는 것**

| 받는 것 | 준 사람 | 없으면 |
|---|---|---|
| DB 스키마 · 시드 대화방 1개 | A (Phase 0) | 시작 불가 |
| `components/Avatar.tsx` | B (Phase 2-3) | 임시 원형 표시로 대체 후 교체 |
| 수락 → 대화방 생성 흐름 | C (Phase 4) | 시드 대화방으로 개발하고, 나중에 실제 흐름으로 재확인 |

**내가 남에게 넘기는 것**

| 넘기는 것 | 받는 사람 | 언제 |
|---|---|---|
| `app/chat/[id]/page.tsx` | B (여기에 신고 진입점을 붙인다) | Phase 5 끝 |

### 5-3 실시간

구독 코드:

```ts
// app/chat/[id]/page.tsx
supabase
  .channel(`room:${conversationId}`)
  .on('postgres_changes',
      { event: 'INSERT', schema: 'public', table: 'messages',
        filter: `conversation_id=eq.${conversationId}` },
      ({ new: msg }) => setMessages(prev => [...prev, msg]))
  .subscribe()
```

- [ ] 위 구독 코드 추가
- [ ] 컴포넌트 언마운트 시 `supabase.removeChannel()`로 구독 해제
- [ ] 내가 보낸 메시지가 두 번 그려지지 않게 처리 (id 중복 제거)
- [ ] 🔍 창 두 개를 나란히 놓고 한쪽에서 전송 → 다른 쪽에 **새로고침 없이** 즉시 표시
- [ ] 🔍 안 뜨면 `alter publication supabase_realtime add table messages;`가 실행됐는지 먼저 확인
- [ ] 🔍 같은 메시지가 두 번 안 뜬다
- [ ] 🔍 대화방을 나갔다 다시 들어와도 구독이 중복되지 않는다 (메시지가 2번씩 늘면 해제가 안 된 것)
- [ ] 💾 `feat: 실시간 메시지 수신`

## Phase 8 — 대면 밸런스게임

**끝나면 보이는 것:** 대화방에서 "만났어요"를 누르면 큰 글씨 질문이 뜨고, 넘기기로 계속 다음 질문을 본다. 답을 입력하는 곳이 없다.

**이 화면은 폰을 책상에 놓고 두 사람이 함께 보는 화면이다.** 혼자 보는 화면이 아니므로 글씨 크기와 세로 배치가 전부다.

- [ ] `app/chat/[id]/page.tsx` 상단에 "만났어요" 버튼 추가 → `/chat/[id]/meet`
- [ ] `app/chat/[id]/meet/page.tsx` — `balance_questions` 30개를 한 번에 불러온다
- [ ] 불러온 순서를 무작위로 섞고 인덱스로 하나씩 보여준다
- [ ] 질문을 화면 전체에 크게 (선택지 A / "vs" / 선택지 B, 최소 32px)
- [ ] 세로 화면 기준 레이아웃
- [ ] 버튼은 "다음 질문" 하나만 만든다
- [ ] 30개를 다 보면 "질문을 다 봤어요" + "처음부터 다시" 버튼
- [ ] 나가기 버튼으로 대화방 복귀
- [ ] 🔍 대화방에서 "만났어요" → 질문 화면으로 넘어간다
- [ ] 🔍 **폰을 책상에 놓고 팔 하나 거리에서 글씨가 읽힌다** (실제로 해본다)
- [ ] 🔍 "다음 질문"을 30번 눌러도 같은 질문이 두 번 안 나온다
- [ ] 🔍 답을 입력하거나 고르는 UI가 화면 어디에도 없다 (SPEC 4.6)
- [ ] 🔍 화면을 나갔다 다시 들어와도 Supabase 어느 테이블에도 데이터가 안 쌓인다
- [ ] 💾 `feat: 대면 밸런스게임 화면`

## 절대 어기면 안 되는 것

- **밸런스게임 답을 저장하지 않는다.** 선택 버튼도, 입력창도, 서버 호출도 만들지 않는다. 말로 하는 것이 목적이고, 앱은 질문만 던지고 빠진다 (SPEC 4.6)
- **읽음 확인 표시를 만들지 않는다.** "안 읽은 개수"는 나에게만 보이는 내 정보이고, "상대가 읽었음"은 SPEC 제외 항목이다 (SPEC 4.4)
- **사진·파일·이모티콘 전송을 만들지 않는다.** v1은 텍스트만이다 (SPEC 4.4)
- **메시지 삭제·수정을 만들지 않는다** (SPEC 4.4)
- **내 대화방이 아닌 곳에 주소로 들어갈 수 없게 한다.** 화면에서 링크를 숨기는 것만으로는 부족하고 서버에서 참여자를 확인한다
